# Break configuration visibility across attendance reports

The follow-up exposes the working-time report’s configured lunch minimum and source metadata, then expands all three HRMS views to distinguish actual gaps, configured lunch, and deducted break time. The calculator and payroll paths are unchanged: open-only modern sessions still return zero credited and deducted minutes, while completed evidence deducts `max(actualBreakMinutes, configuredLunchMinutes)`. The live one-punch/open-session shape receives the pending badge, but the badge and configuration fallbacks do not cover all response shapes accurately. No P0 or P1 regression was found; two confirmed P2 presentation regressions and a P2 regression-test gap remain.

Watch for: **confirmed (P2)** later open sessions and legacy punch-in-only rows are not marked pending; **confirmed (P2)** missing configuration is displayed as `0m configured`; **confirmed (P2)** the bug’s open/completed/legacy states have no automated regression coverage.

**Verdict**: NEEDS_CHANGES

## High-level view

`getWorkingTimeReport` adds `report.configuredLunchMinutes` and per-day `workingTimeSource` without removing existing fields. Attendance and salary calculations still use the shared calculator, so this diff does not alter lunch deduction or payroll behavior.

The views now label actual, configured, and deducted minutes separately. The known current-day open-only session shows zero worked/zero deducted with `Punch-out pending`, while completed multi-session days expose actual inter-session gaps.

Pending state is inferred from data quality plus a non-empty session array rather than an actual open punch. **Confirmed (P2):** a later open session looks final, and a legacy `punchIn` without `sessions` also lacks the pending marker.

Configuration fallbacks turn absent data into a definite zero. **Confirmed (P2):** this contradicts the 45-minute setting on non-working rows that are not enriched, older attendance responses, and a frontend using the pre-change report response.

## Open punch state is narrower than the UI explanation

The new badges require `workingTimeDataQuality === "no-completed-session"`; the attendance views additionally require `record.sessions?.length > 0`, and the working-time report requires `d.sessions.length > 0` (`WorkingTimeReport.jsx:170-178`, `AttendancePage.jsx:1255-1263`, `AttendanceMasterPage.jsx:1224-1232`). This is **confirmed (P2)** for a completed morning interval followed by an open afternoon interval: the calculator reports `dataQuality: "calculated"` as soon as any completed interval exists, so the open punch is not marked even though the explanation says the row remains pending until final punch-out.

The condition is also **confirmed (P2)** to miss legacy punch-in-only records. The calculator returns `no-completed-session` for `punchIn.time` without `punchOut.time` or session facts, but the empty `sessions` array suppresses the badge. Expose the calculator’s `hasOpenSession` in both APIs, or derive open state from session facts with a legacy punch fallback.

## Unknown configuration is presented as a zero-minute policy

The working-time summary renders `report.configuredLunchMinutes ?? 0`, and rows eventually fall back to zero (`WorkingTimeReport.jsx:99`, `WorkingTimeReport.jsx:188`). This is **confirmed (P2)** during frontend/backend version skew: the pre-change report has per-day configured lunch but no report-level field, so the summary says `0m` while rows can say `45m`. Derive a known value from a day or display an unavailable state.

The attendance tables now visibly assert `0m configured` (`AttendancePage.jsx:1277`, `AttendanceMasterPage.jsx:1246`). This is **confirmed (P2)** for Absent and Leave rows because `withCalculatedTime` only enriches Present, Late, and Half Day records, and for legacy responses without calculation metadata. Hide break math where it is inapplicable, provide report-level configuration, or preserve unknown as unknown.

## Regression coverage for the reported break-detection states

No automated tests accompany the API and JSX follow-up. This is a **confirmed (P2)** gap for configured lunch at 45 minutes, open-only zero credit/deduction with a pending marker, completed multi-session gaps, later open sessions, and missing legacy fields. Add focused API/calculator assertions and rendering coverage.
