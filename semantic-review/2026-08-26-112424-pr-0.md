# Stable open-session metadata for HRMS break displays

This follow-up aligns the executable legacy-open expectation with the retained stored-hours policy and normalizes open-session metadata to a strict boolean. HRMS reports expose configured lunch independently from actual gaps and deducted time, while modern and legacy open punches remain visibly pending. Missing metadata no longer invents a zero-minute configuration, and payroll calculation code is unchanged. The existing executable regression assertions complete successfully.

Watch for: No remaining P0, P1, or P2 concerns in the scoped change.

**Verdict**: APPROVED

## High-level view

`calculateAttendanceTime` now guarantees `hasOpenSession` is `true` or `false`, and both APIs forward it. Modern open-only, completed-plus-open, and legacy punch-in-only records therefore share one pending-state contract.

The legacy no-session path intentionally keeps stored `workingHours` credited while independently marking the punch open. Its assertion now expects 480 minutes, `hasOpenSession: true`, and `stored-hours-only`, preserving payroll compatibility.

Live configured lunch is presented separately from actual gaps and deducted time. Attendance views suppress break math without metadata; Working Time resolves report-level configuration, then a day fallback, then an unavailable marker.

## Open-punch state is independent from credited-time provenance

Wrapping the full open-session expression in `Boolean(...)` prevents stored-only, completed, and empty records from producing `undefined` and losing the field during JSON serialization.

Modern session facts remain authoritative: open-only returns zero with `no-completed-session`, completed-plus-open credits only completed intervals, and legacy-open can be both pending and credited from stored hours. All three HRMS tables render `Punch-out pending` from this independent flag.

## Live lunch policy remains distinct from observed and deducted breaks

Attendance responses carry `configuredLunchMinutes`, `actualBreakMinutes`, and `deductedBreakMinutes`; working-time responses also carry report-level configuration. The views label all three values separately. Attendance and Attendance Master show `Not applicable` when calculation metadata is absent, while Working Time shows an em dash when neither report nor day metadata supplies configuration.

## Payroll behavior and executable assertions

The backend diff changes only boolean normalization and the legacy-open assertion; `hrmsSalaryCalc.js` has no diff. `node crm_backend/scripts/simulateHalfDayScenarios.mjs` passes zero-credit, modern open-only, legacy-open, completed-plus-open, legacy/stored fallback, gap, overlap, and settings-change assertions. A direct JSON check confirmed non-open results retain `hasOpenSession: false` after serialization. Targeted ESLint found no errors in the three affected views; two warnings are on unchanged `AttendancePage` hook lines.
