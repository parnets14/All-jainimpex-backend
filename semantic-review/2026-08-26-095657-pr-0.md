# Canonical lunch-adjusted working time across HRMS and payroll

The change centralizes credited working time as the completed punch span minus the larger of configured lunch or merged-session gaps, then applies it to attendance APIs, reports, exports, half-day logic, and hourly payroll. Settings are read at response or payroll time so historical punch-backed records recalculate dynamically, while stored-hours-only history retains its value without another lunch deduction. The corrected fixture now adds lunch to its synthetic punch span, so “worked” means credited rather than elapsed minutes. The follow-up also resolves the prior pass’s late-report status-scope and sub-minute mismatches without coupling late or OT clocks to credited time.

Watch for: **confirmed (P1)** zero credited minutes bypass both half-day and legacy shortfall deductions; **confirmed (P2)** records with sessions but no completed session can fall through to legacy or stored hours; **confirmed (P2)** reduced-quality fallback is not surfaced in HRMS screens or salary audit data; **confirmed (P2)** the manual simulation omits zero/open/fallback cases and there is no automated regression suite.

**Verdict**: NEEDS_CHANGES

## High-level view

`calculateAttendanceTime` now supplies model persistence, attendance responses, working-time totals, salary preview/final generation, and hourly payslip totals. It merges overlaps and distinguishes actual from deducted break time, but its fallback precedence can override an open-only modern session set with legacy data.

Half-day and shortfall calculations consume the canonical value only when it is greater than zero. A short completed record whose entire span is absorbed by lunch is therefore treated more favorably than a one-minute credited record.

Stored-hours-only results are tagged in backend attendance/report payloads. The frontend and salary slip shape discard that signal, so historical reports and payroll do not distinguish retained legacy values from punch-derived time.

The corrected simulation validates positive credited-minute bands and different shift lengths, but does not exercise the zero-credit boundary or the fallback/data-shape contract.

## Zero canonical minutes escape half-day and shortfall deduction

`computeAttendanceAdjustments` calculates the canonical value and gates all half-day and legacy shortfall behavior behind `worked > 0` (`crm_backend/utils/hrmsSalaryCalc.js:263-299`). This is **confirmed (P1)**: a completed 09:00–09:30 record with a 60-minute lunch correctly produces zero credited minutes, but the adjustment result contains zero `halfDayCount`, zero `halfDayShortMinutes`, and zero `shortfallMinutes`. Payroll has already counted a Present/Late/Half Day row as present, so fixed and daily salary do not recover the missing required minutes elsewhere.

Zero credited minutes consequently produce no deduction while one credited minute enters the below-half band and deducts nearly the full required day. Classification must accept zero for completed records. If open-only rows are handled as absences, distinguish them through completed-session/data-quality state rather than the numeric value.

## Open session facts can be replaced by stale fallback values

`calculateAttendanceTime` records `hasOpenSession`, but when no completed interval exists it tries `punchIn`/`punchOut` and then stored `workingHours` (`crm_backend/utils/attendanceTime.js:30-64`). This is **confirmed (P2)**: `{ sessions: [{ in: ... }], punchIn: ..., punchOut: ... }` returns the legacy punch span, and the same open session with positive stored hours returns that value. Both violate the open-only-zero rule when `sessions` is the authoritative source.

A legacy or manually created same-day row can acquire this shape because punch-in appends a session before the pre-save calculator runs without first clearing legacy aliases. Legacy and stored fallbacks should apply only when `sessions.length === 0`; an existing session set with no completed pair should return `no-completed-session`, while completed sessions plus a trailing open session should continue using only completed intervals.

## Stored-only quality is not visible where decisions are made

The fallback retains `workingHours` and marks it `stored-hours-only` (`crm_backend/utils/attendanceTime.js:47-64`), and attendance/report serializers expose `workingTimeDataQuality`. This is **confirmed (P2)** because `AttendancePage`, `AttendanceMasterPage`, and `WorkingTimeReport` render/export only worked and break numbers, while salary data persists `hoursWorked` without a source or quality summary (`crm_backend/queue/salaryQueueFallback.js:503-520`). A retained historical value can affect an hourly payslip while appearing indistinguishable from punch-derived time.

Surface the flag in attendance/report rows and CSV, and persist an aggregate or per-day warning with preview/final salary data.

## Simulations do not protect the canonical contract

The fixture correction adds 60 minutes to each single-session span before production code derives credited time (`crm_backend/scripts/simulateHalfDayScenarios.mjs:29-49`). Coverage is **confirmed (P2)** to remain incomplete because scenarios start at 120 credited minutes and only print output; the backend package has no test script or matching test/spec files.

Not tested: zero credited minutes, pure and mixed open-only records, completed work plus a trailing open session, configured lunch zero, no break versus shorter and longer gaps, overlaps, stored-only quality propagation, settings-change recalculation, and preview/final salary parity. Add executable assertions around the shared calculator and salary adjustment helper; keep the simulation as demonstration output.
